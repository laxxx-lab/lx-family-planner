# Internationalisation (i18n)

LX uses [i18next](https://www.i18next.com/) and
[react-i18next](https://react.i18next.com/) for the interface. English and
German are maintained as complete languages; German remains the installation
default and fallback for existing deployments.

Simplified Chinese (`zh`) is available as an optional interface language.
It does not change the German installation default or saved device choices.

German version: [i18n.de.md](i18n.de.md)

## Selecting a language

Users can switch the language before login and from the main header. The choice
is stored on that device as `lx_family_language` and takes precedence over the
installation default.

Set the default interface and background-notification language with:

```bash
APP_LANGUAGE=en
```

`GET /api/config` exposes the installation default. Local Vite development can
also use `VITE_APP_LANGUAGE=en`.

Every API request includes `X-LX-Language`. The server uses this request-local
language for validation and API errors, while scheduled reminders and other
background work use `APP_LANGUAGE`. The request context is isolated with
`AsyncLocalStorage`, so simultaneous English and German devices cannot change
each other's responses.

## Catalogue layout

```text
src/i18n/
  index.js
  resources.js
  locales/
    de/<namespace>.json
    en/<namespace>.json

server/
  i18n.js
  locales/de.json
  locales/en.json
```

Frontend namespaces are grouped by product area: `common`, `calendar`, `meals`,
`tasks`, `shopping`, `chat`, `dashboard`, `familyLife`, `familyMail`,
`familyTree`, `board`, `admin`, `adminCloud`, `auth`, `notifications`, `context`,
`chrome`, `profile`, `widgets` and `shared`.

Add every new namespace to `resources.js` for both languages. Static imports are
intentional: Node-based tests also import hooks and utilities outside Vite.

## Translation rules

- Use semantic keys such as `meals.weekday.monday`, never source text as a key.
- Use `useTranslation()` in components and `i18n.t()` only in non-component
  modules where passing text in is impractical.
- Use interpolation and `_one` / `_other` plural forms rather than string
  concatenation.
- Format dates, numbers, currency and sorting through
  `src/utils/formatting.js`; never hard-code `de-DE` in UI code.
- Add English and German together. `npm run check:i18n` rejects mismatched
  catalogue keys.
- Do not expose a new language in the switch until its full catalogue is
  reviewed and has an owner who can maintain it.

Example:

```jsx
import { useTranslation } from 'react-i18next';

const { t } = useTranslation('meals');
return <button>{t('addRecipe')}</button>;
```
