# Internationalisierung (i18n)

Die Oberfläche wird über [i18next](https://www.i18next.com/) und
[react-i18next](https://react.i18next.com/) übersetzt. Deutsch ist die
Standard- und Fallback-Sprache.

## Sprache auswählen

Die Sprache wird pro Installation über die Umgebungsvariable
`APP_LANGUAGE` gesetzt (`de`, `en`, `fr`, `es`, `it`, `nl`, `pl` oder
`zh` für vereinfachtes Chinesisch; Standard: `de`):

```bash
# .env
APP_LANGUAGE=en
```

Der Server liefert die Einstellung über `GET /api/config` aus; die App
übernimmt sie beim Start. Für die lokale Vite-Entwicklung ohne Server kann
alternativ `VITE_APP_LANGUAGE=en` gesetzt werden. Eine im Browser unter
`lx_family_language` (localStorage) gespeicherte Wahl hat Vorrang vor der
Server-Einstellung.

## Aufbau der Übersetzungsdateien

```
src/i18n/
  index.js              # i18next-Initialisierung
  resources.js          # statische Importe aller Kataloge
  locales/
    de/<namespace>.json  # Quelle der Wahrheit (Deutsch)
    en/<namespace>.json  # Englische Übersetzung, identische Schlüssel
```

Namespaces sind nach Funktionsbereichen geschnitten (`common`, `calendar`,
`meals`, `tasks`, `shopping`, `chat`, `dashboard`, `familyLife`, `familyMail`,
`familyTree`, `board`, `admin`, `adminCloud`, `auth`, `notifications`,
`context`, `chrome`, `profile`, `widgets`, `shared`).

Ein neuer Namespace muss in `resources.js` für **beide** Sprachen eingetragen
werden. Die Kataloge werden bewusst statisch importiert und nicht über
`import.meta.glob` eingesammelt: So lässt sich `src/i18n` auch außerhalb von
Vite laden – etwa in den Node-Tests, die Hooks aus `src/hooks/` importieren.

Der Server hat eine eigene, leichtgewichtige Variante unter
`server/locales/{de,en}.json` für Push-Benachrichtigungen, Erinnerungen und
API-Fehlermeldungen.

## Konventionen

- **Schlüssel sind semantisch**, nicht der deutsche Text:
  `meals.weekday.monday`, nicht `meals.Montag`.
- **In Komponenten** den Hook verwenden:

  ```jsx
  import { useTranslation } from 'react-i18next';

  const { t } = useTranslation('meals');
  <button>{t('addRecipe')}</button>
  <input placeholder={t('common:labels.date')} />
  ```

- **Platzhalter** mit Interpolation statt String-Verkettung:
  `t('greeting', { name })` mit `"greeting": "Hallo {{name}}!"`.
- **Pluralformen** über i18next-Suffixe: `"item_one"` / `"item_other"`.
- **Außerhalb von Komponenten** (z. B. reine JS-Module) `i18n.t(...)` aus
  `src/i18n` importieren – aber bevorzugt Strings in die Komponenten ziehen.
- **Datum, Zahlen, Sortierung** nie mit fest verdrahtetem `'de-DE'`
  formatieren, sondern über die Helfer in `src/utils/formatting.js`
  (`formatDate`, `formatTime`, `formatCurrency`, `getWeekdayNames`,
  `compareStrings`, `toLocaleLowerCase`).
- **Beide Sprachen pflegen**: Jeder Schlüssel muss in `de` und `en`
  existieren. `npm run check:i18n` prüft die Schlüssel-Parität.
