# LX Family 1.21.3

- **Sichere Kalenderrechte:** Nur Erwachsene können Termine anlegen,
  bearbeiten, duplizieren, löschen und ICS-Dateien importieren. Kinder,
  Jugendliche und Wanddisplays lesen den Kalender; direkte API-Aufrufe
  umgehen diese Rechte nicht.
- **Wandansicht wieder bedienbar:** Profilwechsel funktioniert mit den
  bestehenden PIN- und Passwortprüfungen. Themes und Tablet-Kacheln lassen
  sich anpassen. Die Aufgabenansicht zeigt die Familienaufgaben und später
  geplante Aufgaben. Aufgaben können weiterhin auf der Tablet-Startseite
  mit Auswahl des erledigenden Profils abgehakt werden.
- **Lesbare Themes und übersetzte Fehler:** Kalender- und
  Benachrichtigungsbuttons bleiben auch in hellen Akzentfarben lesbar.
  Fehlende Sterne werden in der gewählten Oberflächensprache gemeldet.
- **Android-Aktivierung:** Der Hinweis zur Aktivierung erscheint auch im
  Berechtigungszustand `prompt-with-rationale`.
- **Plattformpakete:** CasaOS, Cosmos und Umbrel erhalten das Patch-Release;
  Unraid verwendet das aktualisierte `latest`-Image.

Native Android-Meldungen benötigen eine Firebase-Konfiguration auf dem
eigenen Server und die aktivierte Geräteverbindung im Profil. Das Anlegen
einer Kalendererinnerung allein aktiviert keine Systemmeldungen. Die
Einrichtung steht in [README.de.md](../../README.de.md#native-android-benachrichtigungen).
In-App-Meldungen funktionieren unabhängig davon. Eine echte Zustellung auf
einem Android-Gerät wurde in dieser Runde nicht geprüft.

Bestehende Familieninhalte und Datenvolumes bleiben erhalten. Der
CalDAV-Testzeitpunkt ist festgelegt, damit die August-Testtermine auch später
innerhalb des getesteten Synchronisierungsfensters bleiben.

## English

Calendar changes and ICS imports now require an adult profile. Wall displays
support secure profile switching, saved themes, tile customization and family
task visibility. Reward errors follow the interface language and theme button
contrast is corrected. Android notification activation also handles a previous
permission denial. Native delivery still requires Firebase server credentials
and an enabled profile device; delivery on a physical Android phone was not
verified in this release round. Existing family data and persistent volumes
are preserved.
